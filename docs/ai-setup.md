# Подключение ИИ-ассистента

Платформа полностью работает без ИИ. Ассистент добавляет:

- ответы по базе знаний со ссылками на источники (страница «Ассистент», кнопка в базе знаний);
- генерацию SQL по вопросу в SQL-редакторе (запрос проверяется защитой и не выполняется сам);
- черновики выводов эксперимента и наблюдений к виджетам дашбордов;
- разметку событий из документа с описанием новой версии (Реестр событий → «Разметка из документа»):
  ИИ сверяет документ с реестром и предлагает новые события и новые параметры, аналитик принимает
  предложения, и они уходят на обычное утверждение руководителю аналитики.

Шлюз говорит с любым **OpenAI-совместимым API** (`/v1/chat/completions`, `/v1/embeddings`), поэтому
модель меняется только переменными окружения. Ниже — два проверенных варианта.

| | A. Yandex AI Studio, Qwen3.6 35B | B. Локальный Ollama, Qwen3 8B |
|---|---|---|
| Где работает модель | облако Yandex Cloud | ваш сервер, данные не уходят наружу |
| Что нужно | аккаунт Yandex Cloud, API-ключ | ~8 ГБ RAM (лучше GPU), 6 ГБ диска |
| Качество SQL | высокое | хорошее для простых вопросов |
| Для чего | демо и пилот на **демо-данных** | установки у клиентов с реальными данными |

> Требование ТЗ (раздел 10): облачные модели — только на демо-данных. На установке с реальными данными
> поставьте `AI_ALLOW_CLOUD=false` — тогда шлюз откажется ходить на внешние адреса.
> Что уходит в модель: вопрос, фрагменты разрешённых пользователю записей базы знаний, схема таблиц
> (имена и типы колонок) и агрегаты эксперимента/виджета. Сырые строки данных в модель не отправляются.

## Вариант A. Yandex AI Studio (Qwen3.6 35B)

### 1. Получить ключ (≈ 5 минут, в консоли Yandex Cloud)

1. Откройте <https://console.yandex.cloud>, выберите (или создайте) **каталог**. Скопируйте его
   **идентификатор** (`b1g…`) — это `folder_id`.
2. **Сервисные аккаунты → Создать**: имя `analytics-ai`, роль **`ai.languageModels.user`**.
3. Откройте аккаунт → **Создать новый ключ → Создать API-ключ**. Область действия (scope):
   `yc.ai.foundationModels.execute`. Скопируйте секрет — он показывается один раз.

### 2. Прописать в `.env`

```dotenv
AI_ENABLED=true
AI_BASE_URL=https://llm.api.cloud.yandex.net/v1
AI_API_KEY=<секрет API-ключа>
AI_PROJECT_HEADER=OpenAI-Project
AI_PROJECT_ID=<folder_id>
AI_CHAT_MODEL=gpt://<folder_id>/qwen3.6-35b-a3b/latest
# семантический поиск по базе знаний (можно оставить пустым — будет полнотекстовый поиск)
AI_EMBEDDING_MODEL=emb://<folder_id>/text-search-doc/latest
AI_ALLOW_CLOUD=true
```

Если провайдер ответит `401` на заголовок `Bearer`, поставьте `AI_AUTH_SCHEME=Api-Key`.

Каталог моделей AI Studio меняется. Если модель отвечает `403 Forbidden`, а ключ рабочий (например,
`gpt://<folder_id>/yandexgpt/latest` отвечает), значит модели с таким именем больше нет: откройте
**AI Studio → Model Gallery → Модели**, карточку нужной модели, и скопируйте её URI в `AI_CHAT_MODEL`.

### 3. Запустить и проверить

```bash
make up          # или docker compose up -d, если стек уже собран
make ai-check    # (True, '') — модель отвечает
make ai-index    # проиндексировать базу знаний сразу (иначе — автоматически раз в 15 минут)
make ai-exam     # экзамен по голден-сету: ≥ 70% — сдан, отчёт в ai-exam-report.md
```

Откройте <http://localhost:8080/assistant> под `analyst@demo.io` / `demo-pass-2026` и спросите
«Что мы узнали из теста нового туториала?».

### Рассуждающие модели (Qwen3.6, DeepSeek)

Такие модели сначала «думают» (поле `reasoning_content`), и только потом пишут ответ. Рассуждения
расходуют лимит `AI_MAX_TOKENS` и время. Если ассистент отвечает ошибкой «израсходовала лимит токенов
на рассуждения» — увеличьте `AI_MAX_TOKENS` или попросите модель рассуждать меньше через
`AI_EXTRA_BODY`. Какой параметр понимает провайдер, проверяется одной командой:

```bash
docker compose exec api python -c "import httpx,os; e=os.environ; [print(x, (lambda c: (c['finish_reason'], len(c['message'].get('content') or ''), len(c['message'].get('reasoning_content') or '')))(httpx.post(e['AI_BASE_URL']+'/chat/completions', headers={'Authorization':'Bearer '+e['AI_API_KEY'],'OpenAI-Project':e['AI_PROJECT_ID']}, json={'model':e['AI_CHAT_MODEL'],'max_tokens':3000,'messages':[{'role':'user','content':'2+2?'}], **x}, timeout=180).json()['choices'][0])) for x in [{}, {'reasoning_effort':'low'}, {'reasoning_effort':'none'}, {'chat_template_kwargs':{'enable_thinking':False}}]]"
```

Выберите вариант, где ответ есть (вторая цифра > 0), а рассуждений меньше всего (третья цифра), и
впишите его в `.env`, например `AI_EXTRA_BODY={"reasoning_effort": "low"}`.

## Вариант B. Локальный Ollama (Qwen3)

```bash
# .env
AI_ENABLED=true
AI_BASE_URL=http://ollama:11434/v1
AI_CHAT_MODEL=qwen3:8b              # на мощном GPU-сервере: qwen3:32b или qwen3:30b-a3b
AI_EMBEDDING_MODEL=nomic-embed-text
AI_ALLOW_CLOUD=false

make up-ai       # поднимает стек с профилем ai и скачивает модели (несколько минут)
make ai-check && make ai-index && make ai-exam
```

Для продакшена с GPU можно заменить Ollama на vLLM (`AI_BASE_URL=http://vllm:8000/v1`,
`AI_CHAT_MODEL=Qwen/Qwen3-32B`) — код менять не нужно.

## Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AI_ENABLED` | `false` | главный выключатель |
| `AI_BASE_URL` | `http://ollama:11434/v1` | адрес OpenAI-совместимого API |
| `AI_API_KEY` | — | ключ (для Ollama не нужен) |
| `AI_AUTH_SCHEME` | `Bearer` | схема заголовка `Authorization` (`Api-Key` для Yandex по желанию) |
| `AI_PROJECT_HEADER` / `AI_PROJECT_ID` | — | заголовок каталога/проекта провайдера (Yandex: `OpenAI-Project`) |
| `AI_CHAT_MODEL` | `qwen3:8b` | модель ответов и черновиков |
| `AI_SQL_MODEL` | = chat | отдельная модель для SQL (например, более крупная) |
| `AI_EMBEDDING_MODEL` | — | эмбеддинги для гибридного поиска; пусто — только полнотекстовый |
| `AI_NO_THINK` | `true` | для Qwen3 отключает длинную фазу рассуждений (быстрее ответы) |
| `AI_MAX_TOKENS` | `8000` | лимит ответа; у «рассуждающих» моделей сюда входят и скрытые рассуждения |
| `AI_EXTRA_BODY` | — | JSON с параметрами провайдера, добавляется в каждый запрос (например, `{"reasoning_effort": "low"}`) |
| `AI_TIMEOUT_S` | `300` | таймаут запроса к модели |
| `AI_ALLOW_CLOUD` | `true` | `false` запрещает облачные адреса (реальные данные клиента) |

## Как это устроено

- **Шлюз** (`backend/app/modules/ai/gateway.py`) — единственное место обращения к модели: таймауты,
  заголовки, запрет облака, стриминг (SSE), удаление блоков `<think>`, учёт токенов.
- **Поиск по базе знаний** (`rag.py`) — записи режутся на фрагменты, индексируются фоновой задачей
  `ai.index_kb`; поиск гибридный (полнотекстовый PostgreSQL + векторный pgvector, слияние RRF)
  и **всегда** ограничен правами пользователя.
- **SQL** — схема источника из каталога, определения метрик семантического слоя и 6 ближайших примеров
  голден-сета (`backend/starter_kit/gaming/golden_sql.yaml`, 99 пар) → модель → защита запросов;
  если защита отклонила запрос, модель получает ошибку и одну попытку исправиться.
- **Журнал** — каждый ответ сохраняется (`ai_interactions`) с оценкой пользователя 👍/👎;
  администратор видит журнал через `GET /api/v1/ai/interactions` и пополняет голден-сет по плохим ответам.
- **Экзамен** — `scripts/ai_exam.py`: для каждого вопроса голден-сета генерируется SQL (примеры подбираются
  без самого вопроса), оба запроса выполняются на демо-данных, результаты сравниваются. Порог — 70%.
