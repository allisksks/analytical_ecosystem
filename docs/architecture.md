# Архитектура

Модульный монолит (ТЗ, раздел 5): один Python-сервис с чёткими границами модулей, отдельно запускаемые
воркеры и AI-шлюз. Делить на сервисы можно позже, когда появится нагрузка.

```
React SPA ──► nginx (/api proxy, один origin) ──► Core API (FastAPI)
                                                   ├─ iam: пользователи, проекты, роли, политики, токены
                                                   ├─ audit: журнал входов, изменений прав, запросов, промптов
                                                   ├─ connectors: плагины источников + каталог
                                                   ├─ query: sqlglot-guard (только SELECT), RLS, маскирование PII, лимиты, кэш
                                                   ├─ semantic: метрики/измерения → SQL под диалект источника
                                                   ├─ bi: дашборды, виджеты, сохранённые запросы
                                                   ├─ kb: 7 типов записей, версии, поиск
                                                   ├─ ems: события, версии, валидация, алерты
                                                   ├─ experiments: дизайнер, мощность, байес/частотный расчёт, SRM
                                                   └─ ai: OpenAI-совместимый шлюз, RAG, text-to-SQL
Хранилища платформы: PostgreSQL 16 + pgvector (метаданные, векторы), Valkey (кэш, очереди), ClickHouse (sync-данные)
Хранилища клиента: ClickHouse, PostgreSQL, MySQL, файлы/S3 через DuckDB …
```

## Ключевые решения

| Решение | Почему |
|---|---|
| Авторизация — один модуль политик в бэкенде (`app/modules/iam/policy.py`), проверка «действие + ресурс + проект» на каждом эндпоинте | ТЗ, раздел 2: фронт только скрывает кнопки |
| Встроенная аутентификация (argon2 + JWT, refresh в httpOnly cookie) и режим OIDC (Keycloak/SSO) через переключатель `AUTH_MODE` | пилот без Keycloak ставится за 30 минут; в крупной компании — SSO |
| Все SQL проходят через Query Service: разбор sqlglot, только SELECT, подстановка RLS, маскирование PII, лимит и таймаут, кэш, аудит | единая точка контроля, в т.ч. для SQL от ИИ |
| Valkey вместо Redis | Redis 7.4+ сменил лицензию; Valkey — BSD, совместим по протоколу |
| React 19 + TypeScript 5.9, CSS Modules + CSS-переменные вместо Tailwind | актуальные версии; дизайн-токены прототипа ВКР, тёмная тема переключением атрибута |
| Клиент API генерируется из OpenAPI 3.1 (`openapi-typescript` + `openapi-fetch`) | типы фронта и бэка не расходятся, CI это проверяет |
| Демо-данные — Parquet + DuckDB | платформа работает «из коробки» без внешней БД; тот же генератор грузит ClickHouse |
| SQL-редактор на CodeMirror 6 вместо Monaco | встроенное автодополнение по схеме каталога, бандл в ~10 раз меньше, работает офлайн без web-workers и CDN |
| Sync-источники (Google Sheets) материализуются в Parquet в хранилище платформы и читаются через DuckDB | на MVP не нужен отдельный конвейер загрузки в ClickHouse; в Этапе 2 sync-коннекторы API (AppMetrica, AppsFlyer) пишут во встроенный ClickHouse |
| PII маскируется хешем MD5 прямо в SQL, а не на выходе | исходные значения не покидают источник, при этом COUNT(DISTINCT) и JOIN по маскированной колонке продолжают работать |
| Таблицы, которых нет в каталоге платформы, недоступны для запросов | «fail closed»: системные таблицы и неописанные схемы закрыты, RLS не обойти через неизвестную таблицу |
| Эксперименты считаются на агрегатах (n, Σx, Σx²) прямо в источнике; байес (Beta-Binomial, нормальная аппроксимация, байесовский бутстрап) + частотные тесты для сверки | идентификаторы пользователей не покидают хранилище, пересчёт дешёвый; ядро сверено с SciPy/statsmodels |
| Сплиттер — sha256(salt:key:user_id) mod 10000, отдельный хеш для варианта | назначение детерминировано и воспроизводимо в SDK; рост доли трафика не перетасовывает уже назначенных |
| Зрелость когорт эксперимента считается от последней даты в данных, а не от «сегодня» | отставание загрузки не даёт недосмотренных пользователей |
| ИИ — через OpenAI-совместимый шлюз, модель задаётся переменными окружения; облако выключается `AI_ALLOW_CLOUD=false` | одна кодовая база для Yandex AI Studio (демо) и локальных Ollama/vLLM у клиента (ТЗ, раздел 10) |
| Поиск для ассистента гибридный: полнотекстовый PostgreSQL + pgvector, слияние RRF; без модели эмбеддингов — только полнотекстовый | работает сразу, качество растёт при подключении эмбеддингов; права проверяются в том же запросе |
| SQL от ИИ только предлагается: проверяется той же защитой запросов, при отказе — одна попытка самоисправления; выполнение — отдельное действие пользователя | ИИ не получает больше прав, чем пользователь; ошибки модели не превращаются в запросы к данным |
| Качество text-to-SQL меряется экзаменом по голден-сету (99 пар) по совпадению результатов выполнения | объективная метрика для выбора модели; порог ТЗ — 70% |
